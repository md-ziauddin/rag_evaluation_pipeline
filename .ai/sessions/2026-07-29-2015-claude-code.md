## Reasoning

The user's actual question was "how many files do I need to update" — a scoping question. A
grep found 14 files mentioning LangChain, but answering "14" without more would have been
misleading: LangGraph doesn't provide equivalents for LangChain's retriever classes or its text
splitter, so "LangGraph instead of LangChain" has two very different readings that change the
size of the work by roughly an order of magnitude — layering LangGraph over the existing
LangChain components (small, additive) vs. dropping LangChain entirely and hand-rolling every
retrieval strategy (large, touches every ADR and doc that named a specific LangChain class).
Per `BOOTSTRAP.md` step 9 / `RULES.md` #12 (stop and ask when a decision is genuinely hard to
undo and the answer isn't already recorded), this was surfaced as an explicit choice rather than
assumed. The project owner chose full replacement.

Given that choice, ADR 0001 was **not** edited in place to say "LangGraph" — the append-only ADR
convention (`docs/engineering/documentation-plan.md`) means a changed decision gets a new
record. ADR 0013 supersedes it; ADR 0001's historical reasoning (why LangChain over LlamaIndex,
at the time) stays intact for context, with only its Status line changed.

## Completed

- All 14 originally-flagged files updated, plus the new ADR 0013 (15 total).
- `pyproject.toml` reflects the new dependency set — no `langchain-*` package remains.
- Every `.ai/` tracking file that referenced the old stack updated to match.
- **Caught by the project owner, then fixed:** the initial scoping grep (case-insensitive
  `"langchain"`) missed three references that named the LangChain class `ChatBedrockConverse`
  without the word "langchain" nearby — `docs/planning/roadmap.md`'s M6 deliverables,
  `docs/planning/task-breakdown.md`'s T6.1, and `.ai/PROJECT.md`'s stack table. Fixed, and
  followed up with a broader sweep (class names, package names, `chain`/`runnable` grep across
  every doc, not just the ones that already matched "langchain") to confirm nothing else was
  missed. Two "chain" hits in `testing-strategy.md`/`system-architecture.md` are generic
  pipeline-sequence language, not the LangChain `Chain` class — left as-is.

**Lesson for next time:** grepping for the literal string "langchain" undercounts a scoping
question like this — it misses any place that named a specific class or package without the
framework's name nearby. A real re-architecture pass needs both: the literal name, and every
class/package name that's specific to what's being replaced.
